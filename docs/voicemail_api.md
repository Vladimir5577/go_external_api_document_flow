# API модуля голосовой почты

Модуль — сквозной прокси в микросервис `go_voicemail_service_document_flow`.
На АТС он не ходит и тело ответа не разбирает, поэтому новые поля и фильтры
микросервиса появляются на фронте без правок здесь.

Публичный префикс прежний:

```text
/spa/api/external-api/voicemail
```

Доступ: JWT микросервиса и роль `ROLE_CITIZEN_APPEAL` (её наследуют `ROLE_ADMIN`
и `ROLE_ANALYTIC`). Разобрав токен, шлюз проставляет в проксируемый запрос:

```text
X-User-Id    клейм id — им подписывается изменение статуса и комментария
X-User-Name  клейм username (логин; ФИО в токене нет)
```

Одноимённые заголовки, присланные клиентом, **затираются**: микросервис своей
авторизации не имеет и верит им, потому что живёт в закрытой сети `voicemail-net`.

## Env

```env
VOICEMAIL_SERVICE_URL=http://voicemail_service:8089
```

`VMAPI_URL` и `VMAPI_TOKEN` переехали в `.env` микросервиса — шлюз про Asterisk
больше ничего не знает.

## Ручки

Проксируется весь префикс целиком, путь не режется. Что именно отдаёт
микросервис — смотреть в его репозитории; на сегодня это:

```text
GET   /health                     состояние, время последней синхронизации
GET   /mailboxes                  справочник ящиков для фильтра
GET   /messages                   список: page, limit, status, mailbox, dateFrom, dateTo
GET   /messages/{id}/audio        mp3 с поддержкой Range
PATCH /messages/{id}              статус и/или комментарий администратора
```

Важное отличие от прежнего поведения: обращения теперь лежат в базе микросервиса,
а не читаются из живого INBOX на АТС. Поэтому у них появились статус и
комментарий, работает пагинация, а прослушанное не пропадает из списка.
Записи забираются с АТС по ночному расписанию самим микросервисом.

## Ошибки

```json
{"error": "текст ошибки"}
```

```text
401  нет JWT или он не прошёл проверку
403  JWT есть, но нет ROLE_CITIZEN_APPEAL
502  микросервис голосовой почты недоступен или не настроен
```

Остальные коды приходят от микросервиса как есть.
